## Disposition taxonomy (scheme used)

- **test gap** — a genuine decision-logic mutant the oracle should catch but currently
  cannot because the relevant input/boundary is untested. The confirmed oracle gaps are
  the two `_parse_retry_after` boundary mutants (by operator: `seconds < 0` →
  `seconds <= 0` and `seconds < 0` → `seconds < 1`), hardened in STAGE 2. Other
  uncovered decision areas (search-budget enforcement, scenario/sources request
  routing) are recognized test gaps that this bounded pilot explicitly **deferred**
  (per VAL-PILOT-007 "unless triage explicitly rejects the candidate tests"); they
  were documented here, not silently dropped. **Follow-up hardening (this feature):**
  the deferred gaps were subsequently closed with behavior-level tests in
  `tests/service/test_searxng_client.py` — `test_search_budget_exhausted_raises_rate_limited`
  (search-budget enforcement, kills `search__mutmut_7/8/9/10`), `test_forwards_scenario_param`
  (kills `search__mutmut_39`), and `test_passes_sources_category_param`
  (kills `search__mutmut_12`). Each test passes on the clean hermetic baseline and fails
  on its retained mutant (verified via scratch apply/revert; production file byte-identical
  afterward), so none of the deferred candidates was rejected.
- **equivalent behavior** — observably identical to the original under the pilot's unit
  oracle for all covered inputs (header-name case-folding, unexercised
  defaults/`.get()` defaults/boundaries, rstrip equivalences, substring-preserving
  detail strings, unset-env `run_id` routing). Each row cites its `mutmut show` diff.
- **invalid mutation** — a literal/constant textual mutation (log/metric/outcome/
  exception-detail text, or an outbound request-param/key literal) that the unit
  oracle's mocked transport never observes and that does not affect the returned
  results/health/error contract or the decision logic; not a faithful, testable defect
  at the unit boundary. Each row cites its `mutmut show` diff.
- **infrastructure limitation** — none: the recorded run reported `segfault=0`,
  `suspicious=0`, `timeout=0`, so the flake rule was not triggered and no survivor is
  infra-attributable.
